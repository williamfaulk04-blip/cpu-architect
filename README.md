# GPU Architect

GPU Architect is a browser-based educational game for CSC 3501. Players assemble a graphics processing unit (GPU) layer by layer by matching components to their functions and learning how GPU hardware works.

## Learning objective

After completing the game, the player should be able to identify major GPU processing, memory, board-level, and cooling components, describe each component's primary responsibility, and explain how the components work together to process and display data.

## How to play

1. Read the functional description in the highlighted socket.
2. Select a component and review its educational definition.
3. Match the correct component to the highlighted socket.
4. Read the Architect Log for explanations, feedback, or corrections.
5. Complete each GPU assembly stage to unlock its achievement.
6. Finish all three stages to view the completed GPU and learn how its components work together.

## Game stages

**Stage 1: Processing Hardware**
- Streaming Multiprocessor
- CUDA Cores
- Tensor Cores
- GPU Cache
- Memory Controller

**Stage 2: Graphics Card Hardware**
- GPU Chip
- Printed Circuit Board (PCB)
- Video RAM (VRAM)
- Voltage Regulator Module (VRM)
- PCIe Connector
- Power Connector
- Display Outputs (HDMI and DisplayPort)

**Stage 3: Cooling Assembly**
- Thermal Paste
- Copper Heat Pipes
- Heatsink

The game includes 15 interactive components across the three stages.

## Scoring system

The planned scoring system starts at 1,000 points. Correct placements earn 100 points, first-attempt placements earn an additional 50 points, incorrect placements subtract 100 points, and completing a stage awards 250 bonus points. The maximum score is 4,000 points.

```bash
pnpm install
pnpm dev
```

Create a production build with:

```bash
pnpm build
```

## GitHub Pages

The repository includes a separate static build so the editable source and the deployed site stay in sync. Run `pnpm build:pages` to create `pages-dist/`. Pushing to `main` triggers the included GitHub Actions workflow, which builds and publishes the game automatically.

## Static-only constraints

GitHub Pages is a static hosting service. GPU Architect must be able to run using the files generated by its production build without requiring a server process on the hosting platform.

The GitHub Pages deployment has the following constraints:

No backend server: GitHub Pages cannot run the Express backend or other server-side application code.

No server-side database: SQLite and other server-side databases cannot be hosted or queried directly by GitHub Pages. Required game data must be included in the static build or retrieved from an accessible external service.

No server-side API routes: Backend endpoints cannot be created or executed on GitHub Pages. Any runtime API requests must use an external service that supports browser requests and appropriate CORS permissions.

No private API keys in frontend code: Environment variables or credentials included in client-side JavaScript are visible to users. Private API keys must not be included in the static build.

Static assets only: The deployment must include the compiled HTML, CSS, JavaScript, and required assets. The game must not depend on files or services available only on a local development machine.

Deployment paths: Asset and navigation paths must work under the GitHub Pages project-site URL, not assume the game is hosted at the domain root.

Build before deployment: Changes must pass the static production build. The GitHub Actions workflow publishes the generated pages-dist/ output; the source files themselves are not served as the running application.

Development features that require a backend may be tested locally, but they must not be treated as available in the GitHub Pages deployment unless an external hosted service provides them.

## Assignment alignment

The game integrates educational content into its central mechanic. Players must identify GPU components, understand their responsibilities, and assemble the graphics card through interactive puzzles rather than answer unrelated quiz questions.

## Accessibility and responsive design

- Visible keyboard focus indicators.
- Reduced-motion support.
- Touch-friendly component selection.
